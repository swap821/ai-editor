## The gate defect this exposed

Flipping the organ green failed, and not because of the evidence.

`validate_ledger` required **every** `live_evidence` row to carry the sha of the
commit under evaluation. That rule cannot be satisfied by any ledger:

1. **It is self-referential.** Recording evidence creates a commit whose sha the
   evidence could not have contained. Demonstrated rather than argued — evidence
   was stamped `af268809` and committed, and the gate then demanded `82b5c431`,
   the sha of the commit that recorded it.
2. **It is history-hostile.** Applying to every row, satisfying it means deleting
   older evidence — including the two `0/5` runs that organ 44's own C10
   deliberately keeps: *"an organ whose evidence trail shows only its best day is
   not an evidence trail."* Squash-merging compounds this: **3 of organ 44's 5
   historical shas are not ancestors of HEAD at all**, their branches having been
   squashed away, so they could never be re-stamped even in principle.

**The branch had never been exercised.** At `67924fe0` and `0b52e320` — including
the 54/54 all-green state — *zero* organs carried `requires_live_evidence`. Since
the 2026-09-01 recount exactly one does, and it was yellow throughout. Nothing
ever had to pass the impossible check.

The rule now anchors currency to the organ's own verification claim: at least one
live row stamped at `last_verified_sha`, which the tip gate separately requires to
be well-formed and an ancestor of HEAD, and which `strict_last_verified` pins to
the evaluated commit at release-tagging time. Older rows stay as record.

**This was changed on the operator's explicit ruling, not unilaterally**, and it
is the only gate change in this campaign.

### What did not get easier

Pinned by tests, and mutation-checked out-of-tree so no disabled guard ever
touched the repository:

* an organ with **no** live evidence — still refused
* **fixture**-labelled evidence — still refused
* evidence **older than the organ's own verification claim** — still refused
  (`test_evidence_older_than_the_verification_claim_fails`)

With the guard removed, that last test stops failing — the refusal comes from the
new rule and nothing else.

The only thing that became possible is the part that was impossible.

## The commit the evidence is stamped at

The cohort executed at `951e4ae6`, a branch tip this repository squash-merged as
`af268809`, so the execution commit is not an ancestor of master and C12 would
reject it. Rather than stamp a commit the run did not happen at, the two were
proven to carry the same code:

```
master   af268809  tree 0022ceca78b1e3641f6a593ccabc5224ab272745
measured 951e4ae6  tree 0022ceca78b1e3641f6a593ccabc5224ab272745
```

Identical trees, so the measured code *is* master's code. Had they differed,
organ 44 would have stayed yellow pending a re-run at the tip. The same check
discharges the squash-drop risk this repo hit on #269, where a squash silently
lost a commit.
