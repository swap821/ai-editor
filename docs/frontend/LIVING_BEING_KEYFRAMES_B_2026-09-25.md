## Design brief carried forward

The user wants an unmistakably living, futuristic GAGOS that still behaves like the supervised, local-first AI-OS: desktop and mobile matter equally; work should be legible while it happens; human authority remains visible and decisive; the existing organism palette and textures are canon. Android 17 / iOS 27 are OS targets only; physical models are TBD.

This board is grounded in the existing app's actual 32/68 desktop working split, mobile focused-workspace/composer arrangement, canonical BeingPresentation, GuidedApprovalPanel, and the current CSS tokens. The body sketch is only a position cue: use the existing organism renderer and assets. The panel proportions/copy are proposals to review at 1440 × 900 and 390 × 844 CSS pixels, not real device captures.

## State → event → visible response

| Keyframe | Gate from current state | Body / attention | Human-readable UI contract |
| --- | --- | --- | --- |
| Resting | No current work or pending approval after stop/continuity precedence; use the rest phase only with current, fresh continuity | Existing rest posture; still | “GAGOS is resting.” Keep conversation available. Stale/offline instead shows its actual stale/degraded state. Never imply connected, ready, or verified merely from the resting pose. |
| Working | Current task is measured as working (actual stream or active/awaiting-capability worker) | Existing conduct posture, attention toward the attended workspace | “GAGOS is working.” Keep one stable task surface and show only actual incoming output. No guessed percentage or decorative worker count. |
| Awaiting permission | A real server-issued pending approval is present | Existing hold posture; attention toward the person; no outward work motion while held | “GAGOS is waiting for your decision.” Keep the real Guided approval dialog, what/where/effect/refusal details, Explain, and the exact “Allow once” / “Don't allow” decisions. Focus alone never grants authority. |

These map to beingFactsFromStores → deriveBeingPresentation → derivePhysicalSnapshot; they do not introduce a parallel activity/approval store. Existing precedence stays authoritative: emergency stop overrides work, pending approval is never replaced by a calm posture, stale/offline state remains explicit, and verification is green only with a real passing verdict. The work plane keeps stable identity as actual stream chunks arrive.

## Interaction and motion contract

- A posture changes only in response to current state. The visible text is a non-color explanation; each choice remains an ordinary accessible control.
- Apply Emil's frequency gate first (productivity surface): high-frequency and keyboard-initiated actions are immediate. No pulse, breathing CTA, looping particles, forced parallax, bounce, or theatrically staged permission.
- If a state change truly needs a transition, keep it one-shot, interruptible, and limited to transform/opacity; do not animate layout geometry. Retain the existing body-motion calibration instead of inventing a second curve. Reduced motion removes optional motion but preserves the same state, content, focus, controls and decision.
- Keep current visible focus, approval focus containment, Stop, composer, and workspace navigation. No UI may cover the measured composer dock; touch controls meet the product's 44 CSS px target.
- A denial, failure, stop, stale mirror, unverified completion and verified completion remain distinct semantic states. This three-keyframe board does not visually merge or waive them.
